\chapter{Introduction to data mining}
\section{Finding a definition of data mining}
While no unique definition exists yet, it is possible to view data mining as the use of efficient techniques for the analysis of very large collections of data and the extraction of useful and possibly unexpected patterns in data in order to make decisions across various areas.
\begin{examplebox}[Descriptive and predictive data mining]
    Descriptive data mining aims to identify patterns and relationships within data using unsupervised learning techniques that can be applied to recommendation systems, such as Netflix or Spotify's engines, to analyse patterns in user behaviour. \newline
    On the other hand, predictive data mining focuses on using past observations to predict a target variable through supervised learning techniques. \newline
    For instance, CERN's \textit{A Large Ion Collided Experiment} analyses heavy-ion collision data to investigate the properties of quark-gluon plasma.
\end{examplebox}
\section{Understanding data types}
Since data can come in different forms, it is necessary to organize it in order to extract meaningful information or patterns. \newline
In particular, data can be seen as a collection of attributes that describe some objects and, depending on the organization paradigm, data can be classified into three main types:
\begin{itemize}
    \item \textbf{Structured data: }Data is organized according to a well-defined schema that is enforced during storage.
    \item \textbf{Semi-structured data: }Data can be organized according to a structural schema, although this organization paradigm may not be enforced during storage.
    \item \textbf{Unstructured data: }Data does not follow a pre-defined structure, requiring a data cleaning procedure to store it as (semi-)structured data before use.
\end{itemize}
\begin{examplebox}[Different data types]
    Examples of data organization can be seen on the InfoStud platform, which enforces strict organization through dedicated constraints on certain types of data, and medical records, which follow some structural patterns but might contain errors or anomalous data. \newline
    By contrast, social media platforms, such as Twitter or Reddit, provide clear examples of unstructured data that do not follow an organizational structure.
\end{examplebox}

\chapter{Algorithms}
\section{Defining algorithms}
An algorithm can be seen as a set of instructions to solve a given problem. \newline
In particular, an algorithm is evaluated based on its correctness, which determines whether the algorithm works on every possible input or not, and its efficiency, which measures the time taken by the algorithm to find a solution to the given problem.
\begin{examplebox}[The maximum value of an array]
    Consider an algorithm that finds the maximum value in an array of $\displaystyle n$ elements:
    \RestyleAlgo{plain}
    \begin{algorithm}[H]
        \KwData{An array $\displaystyle A$ of size $\displaystyle n$}
        \KwResult{$\displaystyle \max(A)$}
    
        $m \gets A[1]$\;
        \For{$i \gets 1$ \KwTo $n$}{
            \If{$A[i] > m$}{
                $m \gets A[i]$\;
            }
        }
        \Return{$m$}\;
    \end{algorithm}
    \noindent The correctness of this algorithm can be proved by induction on the number of steps.
    \begin{itemize}
        \item For the base case, given by $\displaystyle k = 1$, $\displaystyle A[k]$ is trivially the maximum value.
        \item Assuming the algorithm is correct on an input of size $\displaystyle k$, the goal is to prove its correctness on an input of size $\displaystyle (k + 1)$ as well. \newline
        Claim that, after $\displaystyle k$ steps, $\displaystyle m = \max_{i \in \{1, \dots, k\}}(A[i])$: it is possible to see that $\displaystyle m$ will be updated if and only if $\displaystyle A[k + 1] > m$.
    \end{itemize}
    Additionally, looking at the pseudocode allows to bound the running time of this algorithm to at most $\displaystyle 3n + 2$ moves on an input of size $\displaystyle n$.
\end{examplebox}
\noindent Generally speaking, an algorithm is written using pseudocode in order to provide a language-independent idea of the solution to the given problem.
\section{Complexity analysis}
The running time of an algorithm is a function $\displaystyle T(n)$ that describes the number of steps done by the algorithm to solve a problem on an input of size $\displaystyle n$. \newline
Since algorithm efficiency often depends on the code or machine that is used, it is often sufficient to find an estimate of the running time of an algorithm through asymptotic analysis. \newline
\begin{figure}[H]
    \centering
    \includegraphics[width=0.75\linewidth]{images/complexities.png}
    \caption{Visual comparison of common running time growth rates.}
    \label{fig:complexity}
\end{figure}
\noindent Therefore, given a function $\displaystyle g: \mathbb{N} \to \mathbb{R}^+$, it is possible to define the following asymptotic bounds:
\begin{itemize}
    \item \textbf{Upper bound: }$\displaystyle T(n) = O(g(n))$ if it is possible to find $\displaystyle c > 0$ and $\displaystyle n_0 \ge 0$ such that
    \[0 \leq T(n) \leq c \cdot g(n) \text{ } \forall n \ge n_0\]
    \item \textbf{Lower bound: }$\displaystyle T(n) = \Omega(g(n))$ if it is possible to find $\displaystyle c > 0$ and $\displaystyle n_0 \ge 0$ such that
    \[0 \leq c \cdot g(n) \leq T(n) \text{ } \forall n \ge n_0\]
    \item \textbf{Tight bound: }$\displaystyle T(n) = \Theta(g(n))$ if it possible to find $\displaystyle c_1, c_2 > 0$ and $\displaystyle n \ge n_0$ such that
    \[0 \leq c_1 \cdot g(n) \leq T(n) \leq c_2 \cdot g(n) \text{ } \forall n \ge n_0\]
\end{itemize}
\begin{examplebox}[The prefix sum problem]
    The following algorithm computes the prefix sum for an array of $\displaystyle n$ elements:
    \RestyleAlgo{plain}
    \begin{algorithm}[H]
        \KwData{An array $\displaystyle A$ of size $\displaystyle n$}
        \KwResult{An array $\displaystyle S$ of size $\displaystyle n$ such that $S[i] = \sum_{k = 1}^i A[k]$}
    
        $n \gets len(A)$\;
        \For{$i \gets 1$ \KwTo $n$}{
            $S[i] \gets 0$\;
            \For{$j = 1$ \KwTo $i$}{
                $S[i] \gets S[i] + A[j]$\;
            }
        }
        \Return{$S$}\;
    \end{algorithm}
    \noindent Since this solution computes $\displaystyle i \leq n$ operations at each iteration, its running time can be bounded as $\displaystyle T(n) = n^2 + 3n + 2 = O(n^2)$. \newline
    However, since $\displaystyle T(n) = \Omega(n)$, there is a gap between the lower and upper running time bounds, requiring further investigation to find a better or tighter bound. \newline
    For this reason, one can opt for an alternative algorithm that re-uses a previously computed prefix $\displaystyle S[i - 1]$ to compute $\displaystyle S[i]$ in constant time.
    \RestyleAlgo{plain}
    \begin{algorithm}[H]
        \KwData{An array $\displaystyle A$ of size $\displaystyle n$}
        \KwResult{An array $\displaystyle S$ of size $\displaystyle n$ such that $S[i] = \sum_{k = 1}^i A[k]$}
    
        $n \gets len(A)$\;
        $S[1] \gets A[1]$\;
        \For{$i \gets 2$ \KwTo $n$}{
            $S[i] \gets S[i - 1] + A[i]$\;
        }
        \Return{$S$}\;
    \end{algorithm}
    \noindent In fact, this strategy allows to reduce the overall time complexity to the optimal value of $\displaystyle T(n) = \Theta(n)$.
\end{examplebox}
\subsection{The ``gap problem'' in asymptotic analysis}
The gap problem is a situation in which the lower and upper running time bounds of an algorithm do not match, meaning that no tight bound for the algorithm's complexity can be defined.
\begin{examplebox}[Matrix multiplication]
    Suppose you want to compute the product between two matrices of size $\displaystyle n \times n$: the running time of the standard algorithm has a lower bound of $\displaystyle \Omega(n^2)$, which comes from the need to read and write each element in the product matrix, and an upper bound of $\displaystyle O(n^3)$, which denotes the overall computational cost. \newline
    Since the lower and upper bounds do not match, it is not possible to define a tight running time bound for the matrix multiplication algorithm.
\end{examplebox}
\section{Recursive algorithms}
In some cases, it is possible to solve a problem using a recursive algorithm, which makes use of a function that (cyclically) calls itself to solve smaller pieces of a complex problem.
\begin{examplebox}[The Fibonacci sequence]
    It is possible to compute a generic term of the Fibonacci sequence using a recursive algorithm.
    \RestyleAlgo{plain}
    \begin{algorithm}[H]
        \KwData{A non-negative integer $\displaystyle n$}
        \KwResult{The $\displaystyle n^{th}$ element of the Fibonacci sequence}
        
        \If{$n \leq 1$}{
            \Return{$1$}\;
        }
        $f_1 \gets Fibonacci(n - 1)$\;
        $f_2 \gets Fibonacci(n - 2)$\;
        \Return{$f_1 + f_2$}\;
    \end{algorithm}
    \noindent In particular, the running time of this algorithm can be formulated as
    \[T(n) = \begin{cases}
        2 &\quad\text{if $n = 0$ or $n = 1$} \\
        T(n - 1) + T(n - 2) + 3 &\quad\text{if $n \ge 2$} \\
    \end{cases}\]
    Unrolling this formulation reveals that
    \begin{align*}
        T(n)
            &= T(n - 1) + T(n - 2) + 3 \ge T(n - 2) + T(n - 2) = 2T(n - 2) \\
            &\ge 2 \cdot 2T(n - 4) = 4T(n - 4) \ge \dots \ge 2^iT(n - 2i) \ge \dots \\
            &\ge 2^{\frac{n}{2}}T\bigg(n - 2\bigg(\frac{n}{2}\bigg)\bigg) = 2^{\frac{n}{2}}T(0) = 2^{\frac{n}{2} + 1} = O(2^{\frac{n}{2}})
    \end{align*}
    Since the recursive solution runs in exponential time, it can be more convenient to opt for a trivial constant-time algorithm based on Binet's formula or for a linear-time iterative algorithm.
    \RestyleAlgo{plain}
    \begin{algorithm}[H]
        \KwData{A non-negative integer $\displaystyle n$}
        \KwResult{The $\displaystyle n^{th}$ element of the Fibonacci sequence}
        
        \If{$n \leq 1$}{
            \Return{$1$}\;
        }
        $previous \gets0$\;
        $current \gets 1$\;
        \For{$i \gets 2$ \KwTo $n$}{
            $new \gets previous + current$\;
            $previous \gets current$\;
            $current \gets new$\;
        }
        \Return{$current$}\;
    \end{algorithm}
\end{examplebox}
\section{Sorting algorithms}
A sorting algorithm takes an input array and rearranges its elements in (ascending) order, typically using numerical or lexicographical criteria. \newline
These algorithms come in handy to improve the efficiency of other algorithms that require or work well with sorted data.
\subsection{Mergesort}
Mergesort is a ``divide-et-impera'' algorithm that recursively splits an array into smaller sub-lists until they are trivially sorted before merging them back together.

\begin{algorithm}[H]
    \caption{The Mergesort algorithm.}
    \KwData{An array $\displaystyle A$}
    \KwResult{A sorted permutation of $\displaystyle A$}
    
    $n \gets len(A)$\;
    \If{$n \leq 1$}{
        \Return{$A$}\;
    }
    $A_1 \gets A[1, \dots, \lceil\frac{n}{2}\rceil]$\;
    $A_2 \gets A[\lceil\frac{n}{2}\rceil + 1, \dots, n]$\;
    $A_1' \gets MergeSort(A_1)$\;
    $A_2' \gets MergeSort(A_2)$\;
    $A' \gets merge(A_1', A_2')$\;
    \Return{$A'$}\;
\end{algorithm}
\noindent Looking at the pseudocode, the running time of the algorithm can be formulated as
\[T(n) = \begin{cases}
    c &\quad\text{if $n \leq 1$} \\
    2T\big(\frac{n}{2}\big) + c_2n + c_3 &\quad\text{otherwise}
\end{cases}\]
Unrolling the recursive case of this formulation reveals that
\begin{align*}
    T(n) &= 2\bigg(2T\bigg(\frac{n}{4}\bigg) + c_2\frac{n}{2} + c_3\bigg) + c_2n + c_3 \\
         &= 4T\bigg(\frac{n}{4}\bigg) + 2c_2n + 3c_3 \\
         &= \dots \\
         &= 2^iT\bigg(\frac{n}{2^i}\bigg) + ic_2n + (2^i - 1)c_3
\end{align*}
Since the recursive calls can be executed until the base case, where $\displaystyle \frac{n}{2^i} = 1 \Leftrightarrow i = \log_2(n)$, the recurrence can be solved as
\begin{align*}
    T(n) &= 2^{\log_2(n)}T(1) + c_2n\log_2(n) + (2^{\log_2(n)} - 1)c_3 \\
         &= cn + c_2n\log_2(n) + (n - 1)c_3 \\
         &= c_2n\log_2(n) + (c + c_3)n - c_3 = \Theta(n\log n)
\end{align*}
\subsection{Quicksort}
Quicksort is a randomized ``divide-et-impera'' algorithm that randomly selects a pivot and partitions the array into two sub-lists, one containing the elements smaller than the pivot and the other containing the elements greater than the pivot, that are recursively sorted using the same strategy.

\begin{algorithm}[H]
    \caption{The Quicksort algorithm.}
    \KwData{An array $\displaystyle A$}
    \KwResult{A sorted permutation of $\displaystyle A$}
    
    $n \gets len(A)$\;
    \If{$n \leq 1$}{
        \Return{$A$}\;
    }
    Pick a random $p \in \{1, \dots, n\}$\;
    Compare each element in $A$ with $A[p]$, except for the pivot itself\;
    $A_1 \gets [elements \leq A[p]]$\;
    $A_2 \gets [elements > A[p]]$\;
    $A_1' \gets QuickSort(A_1)$\;
    $A_2' \gets QuickSort(A_2)$\;
    \Return{$A_1' + [A[p]] + A_2'$}\;
\end{algorithm}
\noindent In this setting, the worst-case scenario happens if the algorithm consistently splits the array into maximally unbalanced sub-arrays, meaning that the chosen pivot is either the first or the last element in the array, causing the running time to degrade to $\displaystyle O(n^2)$. \newline
However, since the pivot is always chosen uniformly at random, the worst-case scenario tends to be extremely unlikely as the expected running time of this algorithm can be bounded by $\displaystyle \mathbb{E}(T(n)) = O(n\log(n))$.
\section{$\mathbf{NP}$-completeness}
When studying algorithms and computational complexity, (decision) problems can be classified depending on how hard they are to solve. \newline
For this reason, it is possible to define the complexity classes $\displaystyle \mathbf{P}$, which includes all decision problems that can be solved in polynomial time using a deterministic algorithm, and $\displaystyle \mathbf{NP}$, which includes all decision problems for which a proposed solution can be verified in polynomial time. \newline
While it is trivially known that $\displaystyle \mathbf{P} \subseteq \mathbf{NP}$, the question on whether $\displaystyle \mathbf{P} = \mathbf{NP}$ remains open. \newline
In this setting, a problem $\displaystyle \mathbf{X}$ is said to be ``$\displaystyle \mathbf{NP}$-complete'' if $\displaystyle \mathbf{X} \in \mathbf{NP}$ and $\displaystyle \mathbf{X}$ is $\displaystyle \mathbf{NP}$-hard, which means that every problem $\displaystyle \mathbf{Y} \in \mathbf{NP}$ can be reduced to $\displaystyle \mathbf{X}$ in polynomial time.
\begin{examplebox}[The travelling salesman problem]
    When formulated as a decision problem, the travelling salesman problem aims to determine whether a graph $\displaystyle G = (V, E)$ contains a path that visits all node in the graph while maintaining an overall cost of at most $\displaystyle c$. \newline
    Using some polynomial time reductions, it is possible to prove that this problem is $\displaystyle \mathbf{NP}$-complete.
\end{examplebox}
\noindent To prove that a problem $\displaystyle \mathbf{X}$ is $\displaystyle \mathbf{NP}$-complete, it is typically sufficient to show that $\displaystyle \mathbf{X} \in \mathbf{NP}$ and that some problem $\displaystyle \mathbf{Y} \in \mathbf{NP}$ can be reduced in polynomial time to $\displaystyle \mathbf{X}$.
\subsection{Solving $\mathbf{NP}$-complete problems via heuristics}
Based on ``metaheuristics'', which represent high-level algorithmic frameworks for problem solving, heuristics provide a problem-specific rule to solve a $\displaystyle \mathbf{NP}$-complete problem. \newline
While heuristics are easy to implement and can provide acceptable solutions in reasonable time, they do not guarantee optimality and might struggle to generalize on different instances of the problem.
\subsection{Solving $\mathbf{NP}$-complete problems via approximation algorithms}
In the context of optimization problems, a $\displaystyle c$-approximation algorithm is an algorithm that is guaranteed to return a solution within a factor $\displaystyle c$ of the optimal solution in polynomial time.
\begin{examplebox}[Approximating the travelling salesman problem]
    While the travelling salesman problem cannot be solved in polynomial time, there are some approximation algorithms that, for a cost function that satisfies the triangle inequality, are guaranteed to find a solution whose value is at most two times the optimal value.
\end{examplebox}

\chapter{Data structures}
\section{The purpose of data structures}
A data structure is a way of storing and organizing data to optimize or simplify certain tasks. \newline
A data structure is first defined as an ``abstract data type'', which describes the operations supported by the structure, and then implemented as a ``concrete data structure'', which describes how data is stored and the way certain operations are performed.
\section{Lists}
A list is an abstract data type that is used to store a sequence of objects, each indicated by an index, while supporting the following operations:
\begin{itemize}
    \item \texttt{L.insert(x, i)}: The value \texttt{x} gets inserted at position \texttt{i}.
    \item \texttt{L.remove(i)}: The value located in position \texttt{i} gets removed.
    \item \texttt{L.get(i)}: The list returns the value located in position \texttt{i}.
    \item \texttt{L.set(x, i)}: The value located in position \texttt{i} is set to \texttt{x}.
\end{itemize}
A list can be implemented using an array, which is a contiguous data structure where elements are stored sequentially and accessed using a positional index, or using a linked list, which is a non-contiguous data structure where elements can be stored in different memory locations and accessed using pointers.

    \label{tab:list_complexity}
\end{table}
\noindent Overall, arrays are simple to manage but computationally inefficient, whereas linked lists are flexible and efficient but problematic to manage.
\section{Heaps}
A heap is a concrete data structure that stores data using a (binary) tree that satisfies the following structural properties:
\begin{itemize}
    \item The tree is built top-down, starting from the root and and filling each tree level left-to-right before moving to the next one. \newline
    This implies that the height of a tree containing $\displaystyle n$ nodes will be $\displaystyle \lceil\log_2(n)\rceil$.
    \item The value of a node is always greater or equal than the values of its children, which, however, are not necessarily sorted because this property only holds locally.
    \item If a heap is implemented as an array, the child nodes of the element at position $\displaystyle i$ are located at positions $\displaystyle 2i$ and $\displaystyle (2i + 1)$, respectively, whereas the parent node is located at position $\displaystyle \bigg\lfloor\frac{i}{2}\bigg\rfloor$.
\end{itemize}
For this reason, a heap is useful because it allows to implement the Heapsort algorithm for sorting the values in an array.
\section{Priority queues}
A priority queue is an abstract data structure that stores a set of objects, each with an associated priority, while supporting the following operations:
\begin{itemize}
    \item \texttt{Q.insert(x)}: The value \texttt{x} is inserted at the back of the queue.
    \item \texttt{Q.peekMax()}: The queue returns the maximum value.
    \item \texttt{Q.removeMax()}: The queue removes and returns the maximum value.
\end{itemize}
While a priority queue can be implemented using an array or a (doubly) linked list, these data structures tend to be quite inefficient when peeking or removing the maximum value. \newline
For this reason, priority queues are often implemented using heaps because the heap property allows to make queue operations more efficient.

\section{Dictionaries}
A dictionary is an abstract data type that stores pairs of keys, which are unique and immutable objects, and associated values while supporting the following operations:
\begin{itemize}
    \item \texttt{D.set(k, v)}: Key \texttt{k} is assigned value \texttt{k}. \newline
    If the key is not present in the dictionary, this operation acts as an insertion method.
    \item \texttt{D.get(k)}: The dictionary returns the value associated to key \texttt{k}.
    \item \texttt{D.remove(k)}: The dictionary removes key \texttt{k} and the value associated to it.
    \item \texttt{D.exists(k)}: The dictionary checks whether it contains key \texttt{k}.
\end{itemize}
Assuming all keys in a dictionary are numeric values, this data type can efficiently be implemented using an array, which stores each key in the dictionary, and a linked list, which points each key to the corresponding value. \newline
On the other hand, generic non-numeric keys first need to be mapped onto numeric representations, although it is necessary to discard letter case and avoid collisions, which occur when different items are mapped onto the same value. \newline
Therefore, dictionaries are organized using a hash function $\displaystyle h: [0, \dots, 2^m - 1] \to [0, \dots, 2^n - 1]$, typically having $\displaystyle m >> n$, that minimizes the risk of collisions between keys. \newline
For instance, when using a random hash map, the probability of a collision between two keys $\displaystyle x \neq y$ is given by
\[\mathbb{P}(h(x) = h(y)) = \frac{1}{2^n} \text{ } \forall x, y \in [0, \dots, 2^m - 1]\]
However, a random function cannot be used as a hash map because, since it returns a different value upon every call, it is not compatible with the deterministic nature of hash functions.
\begin{examplebox}[Using universal hashing to manage IP addresses]
    An IP address is expressed as a sequence $\displaystyle x = x_1x_2x_3x_4$, which consists of four $\displaystyle 8$-bit values, that are typically mapped to the set $\displaystyle [0, \dots, 255]$. \newline
    The mapping starts with the choice of a prime number $\displaystyle p$, which is slightly larger than $\displaystyle 255$, that is used to sample four weights $\displaystyle \alpha_1, \alpha_2, \alpha_3, \alpha_4$, which are drawn uniformly at random from the set $\displaystyle \{1, \dots, p - 1\}$. \newline
    Therefore, the resulting hash function will be given by
    \[h(x) = \Bigg(\sum_{i = 1}^4 \alpha_ix_i\Bigg) \text{, for which one can prove that } \mathbb{P}(h(x) = h(y)) = \frac{1}{p} \text{ } \forall x \neq y\]
\end{examplebox}
\noindent Overall, hash functions are often handled with buckets, which act as linked lists that store all the key-value pairs associated to the same hash value, so that, if the expected size of each bucket is small, operations can be carried out in constant time.

\chapter{Data relationships}
\section{Distance functions}
Since most data mining problems focus on describing relationships between objects within a ``universe'' $\mathcal{U}$, object discrepancies are measured using a distance function $\displaystyle d: \mathcal{U} \times \mathcal{U} \to \mathbb{R}^+$ such that
\begin{enumerate}
    \item The function is non-negative, meaning that $\displaystyle d(x, y) \ge 0 \text{ } \forall (x, y) \in \mathcal{U} \times \mathcal{U}$, with $\displaystyle d(x, y) = 0$ if and only if $\displaystyle x = y$.
    \item The function is symmetric, meaning that $\displaystyle d(x, y) = d(y, x) \text{ } \forall (x, y) \in \mathcal{U} \times \mathcal{U}$.
    \item The function obeys the triangle inequality, meaning that $\displaystyle d(x, y) \leq d(x, z) + d(z, y) \text{ } \forall x, y, z \in \mathcal{U}$.
\end{enumerate}
\subsection{The $L^p$ distance family}
If $\displaystyle \mathcal{U} = \mathbb{R}^m$, the distance between two $\displaystyle m$-dimensional vectors can be measured using the $\displaystyle L^p$ distance function, which, for an arbitrary $\displaystyle p \in \mathbb{N}$, is defined as
\[d_p(\mathbf{x}, \mathbf{y}) = \Bigg(\sum_{j = 1}^m |\mathbf{x}_j - \mathbf{y}_j|^p\Bigg)^{\frac{1}{p}} = \lVert \mathbf{x} - \mathbf{y} \rVert_p\]
As $\displaystyle p \to +\infty$, the $\displaystyle L^p$ distance function becomes the Chebyshev distance, which is defined as
\[d_{\infty}(\mathbf{x}, \mathbf{y}) = \lim_{p \to +\infty} d_p(\mathbf{x}, \mathbf{y}) = \max_{1 \leq j \leq m}\{|\mathbf{x}_j - \mathbf{y}_j|\} = \lVert \mathbf{x} - \mathbf{y} \rVert_{\infty}\]
\begin{examplebox}[Common distances between two vectors]
    Consider the vectors $\displaystyle \mathbf{x} = \begin{pmatrix}
        3 & 7 & 0 & 2 & 1 \\
    \end{pmatrix}$ and $\displaystyle \mathbf{y} = \begin{pmatrix}
        4 & 5 & 10 & 7 & 3 \\
    \end{pmatrix}$: using some common distances from the $\displaystyle L^p$ family results in
    \begin{align*}
        d_1(\mathbf{x}, \mathbf{y}) &= 1 + 2 + 10 + 5 + 2 = 20 \\
        d_2(\mathbf{x}, \mathbf{y}) &= 1 + 4 + 100 + 25 + 4 = \sqrt{134} \approx 11.57 \\
        d_{\infty}(\mathbf{x}, \mathbf{y}) &= 10
    \end{align*}
\end{examplebox}
\noindent Furthermore, choosing $\displaystyle p = 0$ causes the $\displaystyle L^p$ distance to become the Hamming distance, which is defined as
\[d_0(\mathbf{x}, \mathbf{y}) = |\{j : \mathbf{x}_j \neq \mathbf{y}_j\}|\]
\subsection{The edit distance}
A string can be seen as a sequence whose sub-sequence is any sequence that contains a subset of the characters, not necessarily consecutive, of the string: for two strings $\displaystyle S$ and $\displaystyle T$, a common sub-sequence is any sequence that is a sub-sequence for both $\displaystyle S$ and $\displaystyle T$. \newline
Using this information, it is possible to define the edit distance between two strings $\displaystyle S$ and $\displaystyle T$ as the minimum number of insertions, deletions and, in some cases, substitutions that are needed to transform $\displaystyle S$ into $\displaystyle T$, resulting in
\[ED(S, T) = |S| + |T| -2LCS \text{, where $LCS$ is the length of the longest common sub-sequence.}\]
\begin{examplebox}[Computing the edit distance between two strings]
    Assuming no substitution can be performed, compute the edit distance between the strings $\displaystyle S = CATGA$ and $\displaystyle T = ACTGC$:
    \[S = CATGA \stackrel{del}{\to} ATGA \stackrel{ins}{\to} ACTGA \stackrel{ins}{\to} ACTGAC \stackrel{del}{\to} ACTGC = T\]
    Since transforming $\displaystyle S$ into $\displaystyle T$ required four moves, it will be the case that $\displaystyle ED(S, T) = 4$.
\end{examplebox}
\noindent While computing the edit distance between two strings typically requires exponential time, it is possible to cut complexity down to polynomial time using a dynamic programming algorithm.
\begin{proofbox}
    Given two strings $\displaystyle S$ and $\displaystyle T$, of length $\displaystyle n$ and $\displaystyle m$ respectively, define $\displaystyle S^i$ as the sub-sequence containing the first $\displaystyle i$ characters of $\displaystyle S$ and $\displaystyle T^j$ as the sub-sequence containing the first $\displaystyle j$ characters of $\displaystyle T$: it is possible to prove by induction that the edit distance between $\displaystyle S^i$ and $\displaystyle T^j$ can be recursively computed as
    \[ED(S^i, T^j) = \begin{cases}
        i &\quad\text{if $j = 0$} \\
        j &\quad\text{if $i = 0$} \\
        ED(S^{i - 1}, T^{j - 1}) &\quad\text{if $i, j > 0$ and $S[i] = T[j]$} \\
        1 + \min\{ED(S^{i - 1}, T^j), ED(S^i, T^{j - 1})\} &\quad\text{if $i, j > 0$ and $S[i] \neq T[j]$} \\
    \end{cases}\]
    Knowing that $\displaystyle T(i, j) = c + T(i - 1, j) + T(i, j - 1)$, let $\displaystyle N = i + j$ and write
    \[T(i, j) = T(N) = 2T(N - 1) + c \ge 2T(N - 1) \ge 4T(N - 2) = \dots = 2^lT(N - l)\]
    Since the recursive calls can go on until one of the strings becomes empty, which happens after $\displaystyle l \ge \min\{n, m\}$ steps, the recursive algorithm will require $\displaystyle T(n, m) = \Omega(2^{\min\{n, m\}})$ time. \newline
    However, by looking at the recursive definition of $\displaystyle ED(S^i, T^j)$, one can implement the recursive call using a $\displaystyle (n + 1) \times (m + 1)$ table of optimal values, resulting in $\displaystyle O(nm)$ complexity.
\end{proofbox}
\noindent It should be noticed that, despite a small change in the recursive formulation, this strategy can be applied even when the edit distance allows to perform substitutions as well.
\section{Similarity functions}
Object similarities can be described using a similarity function $\displaystyle s: \mathcal{U} \times \mathcal{U} \to \mathbb{R}^+$ such that
\begin{enumerate}
    \item The function is non-negative, meaning that $\displaystyle s(x, y) \ge 0 \text{ } \forall (x, y) \in \mathcal{U} \times \mathcal{U}$, and takes maximum value when $\displaystyle x = y$.
    \item The function is symmetric, meaning that $\displaystyle s(x, y) = s(y, x) \text{ } \forall (x, y) \in \mathcal{U} \times \mathcal{U}$.
\end{enumerate}
Additionally, since similarity functions are often normalized, they can be turned into distance functions by setting $\displaystyle d(x, y) = 1 - s(x, y)$.
\subsection{The Jaccard index}
When working with set data, the Jaccard index can be used to measure the similarity between the elements of two sets $\displaystyle A$ and $\displaystyle B$ by computing
\[s(A, B) = \frac{|A \cap B|}{|A \cup B|}\]
In particular, the Jaccard index can be expressed as a distance by setting
\[d(A, B) = 1 - s(A, B) = 1 - \frac{|A \cap B|}{|A \cup B|} = \frac{|A \cup B| - |A \cap B|}{|A \cup B|} = \frac{|A| + |B| - 2|A \cap B|}{|A \cup B|}\]
\subsection{The cosine similarity}
If $\displaystyle \mathcal{U} = \mathbb{R}^m$, the cosine similarity measures how similar the directions of two vectors are in terms of the angle between them. \newline
Using the dot product, this metric can be formulated a
\[\mathbf{x} \cdot \mathbf{y} = \lVert \mathbf{x} \rVert_2 \lVert \mathbf{y} \rVert_2 \cos(\theta) 
\quad \implies \quad 
\cos(\theta) = \frac{\mathbf{x} \cdot \mathbf{y}}{\lVert \mathbf{x} \rVert_2 \lVert \mathbf{y} \rVert_2} = \frac{\sum_{i = 1}^m \mathbf{x}_i\mathbf{y}_i}{\sqrt{\sum_{j = 1}^m \mathbf{x}_j^2}\sqrt{\sum_{j = 1}^m \mathbf{y}_j^2}}\]
Therefore, this similarity will be maximum when the two vectors are parallel, meaning that they point towards the same direction, and minimum when the two vectors are anti-parallel, meaning that they point towards different directions.

\chapter{Text mining}
\section{Handling text data}
Documents are typically processed using the ``bag-of-words'' model, which considers raw text as a vector that counts the occurrence of each word in the document. \newline
However, before creating the vector, the extracted raw text first undergoes a pre-processing pipeline that normally consists of the following steps:
\begin{enumerate}
    \item \textbf{Tokenization: }The document is split into a sequence of words or tokens.
    \item \textbf{Stopword removal: }Common words that provide little semantic value are removed from the document in order to reduce computational costs and noise.
    \item \textbf{Normalization: }Text features are standardized in order to avoid syntax-related or case-sensitive mismatches.
    \item \textbf{Stemming: }Words are truncated to their root in order to group similar concepts together.
\end{enumerate}
For this reason, text mining is often performed using the tools provided by the \texttt{nltk} library.
\section{The search engine problem}
Given a corpus of $\displaystyle n$ pre-processed documents $\displaystyle \mathcal{C} = \{D^i\}_{i = 1}^n$ and a query $\displaystyle \mathcal{Q}$, a search engine aims to find the $\displaystyle k$ documents in the corpus that are closest to the query. \newline
This problem can be interpreted as a ``nearest neighbours'' problem, which measures relevance in terms of geometric proximity, or as a ``Boolean algorithm'', which evaluates queries using dedicated data structures.
\subsection{The nearest neighbours formulation}
Using the ``vector space'' model, which treats each document $\displaystyle D^i \in \mathcal{C}$ as a text vector $\displaystyle \mathbf{d}^i \in \mathbb{R}^m$ within a vocabulary of terms, the search engine problem can be solved as a nearest neighbours problem. \newline
However, checking document relevance using the Euclidean distance tends to yield misleading results because the algorithm ignores document sizes and term relevance.
\begin{figure}[H]
    \centering
    \includegraphics[width=0.4\linewidth]{images/documents_vector_space.png}
    \caption{The search engine problem as a nearest neighbours problem in $\displaystyle \mathbb{R}^2$.}
    \label{fig:documents_vector_space}
\end{figure}
\noindent Concerning the first issue, one can prioritize vector directions and model proximity between two documents $\displaystyle D^i, D^j \in \mathcal{C}$ by measuring the cosine similarity between their text vectors, meaning that
\[s(D^i, D^j) = \cos(\theta) = \frac{\mathbf{d}^i \cdot \mathbf{d}^j}{\lVert \mathbf{d}^i \rVert_2\lVert \mathbf{d}^j \rVert_2}\]
The second problem can instead be addressed using the ``TF-IDF'' representation: rather than viewing each text vector as a collection of raw frequencies $\displaystyle TF_j^i$, which simply measure the occurrence of term $\displaystyle j$ in document $\displaystyle D^i$, it is possible to introduce a sequence of non-negative weights $\displaystyle w_1, \dots, w_m$ such that a text vector can be formulated as
\[\mathbf{d}_j^i = TF_j^iw_j = TF_j^i\log\Bigg(\frac{n}{n_j}\Bigg) \text{, where $n_j = |\{i: \mathbf{d}_j^i > 0\}|$.}\]
Knowing that a query $\displaystyle \mathcal{Q}$ can be treated as a text vector $\displaystyle \mathbf{q}$, it is possible to formulate the nearest neighbours problem using the following algorithm:

\begin{algorithm}[H]
    \caption{The search engine problem as a nearest neighbours problem.}
    \KwData{A corpus $\displaystyle \mathcal{C} = \{\mathbf{d}^i\}_{i = 1}^n$, a query vector $\displaystyle \mathbf{q}$ and an integer $\displaystyle k \in \mathbb{N}$.}
    \KwResult{The $\displaystyle k$ closest documents to $\displaystyle \mathbf{q}$.}

    $scores \gets [0] * n$\;
    \For{$i \gets 1$ \KwTo $n$}{
        $scores[i] \gets \cos(\mathbf{q}, \mathbf{d}^i)$\;
    }
    $scores \gets sort(scores)$\;
    \Return{the indices of the $k$ closest documents}\;
\end{algorithm}
\noindent While this approach is correct and easy to implement, its running time of $\displaystyle O(nm)$ makes it very inefficient for real-life search engines.
\subsection{The Boolean algorithm}
An alternative formulation of the search engine problem consists of finding the documents in the corpus that contain all the terms in the query vector.

\begin{algorithm}[H]
    \caption{The search engine problem as a Boolean algorithm.}
    \KwData{A corpus $\displaystyle \mathcal{C} = \{\mathbf{d}^i\}_{i = 1}^n$, a query vector $\displaystyle \mathbf{q}$ and an integer $\displaystyle k \in \mathbb{N}$.}
    \KwResult{All the documents that contain each term in $\displaystyle \mathbf{q}$.}

    $results \gets \{\}$\;
    \For{$i \gets 1$ \KwTo $n$}{
        \If{$\mathbf{d}^i$ contains all terms of $\mathbf{q}$}{
            $results \gets results \cup \{i\}$\;
        }
    }
    \Return{$results$}\;
\end{algorithm}
\noindent While this approach has a similar complexity to the nearest neighbours formulation, its efficiency can be improved by introducing an ``inverted index'' data structure that, for each term in the vocabulary, stores a posting list containing all the documents that contain that term.
\begin{figure}[H]
    \centering
    \includegraphics[width=0.4\linewidth]{images/invertex_index.png}
    \caption{The ``inverted index'' data structure.}
    \label{fig:inverted_index}
\end{figure}
\noindent In fact, using inverted indexing allows to reduce the complexity of a query to the order of the sum of the lengths of the matching posting lists. \newline
In particular, since this data structure can handle any Boolean query, it can be used to optimize the nearest neighbours formulation as well, focusing exclusively on the documents that share at least one term with the query and for which $\displaystyle \cos(\mathbf{q}, \mathbf{d}^i) > 0$. \newline
Therefore, for each term in the query, the posting list now stores both the matching documents and the corresponding weighted frequency scores so that, since the length of the query does not influence the final scores, it is sufficient to compute
\[\cos(\theta) \propto \frac{\mathbf{q} \cdot \mathbf{d}^i}{\lVert \mathbf{d}^i \rVert_2} = \frac{\sum_{j = 1}^m \mathbf{q}_j \cdot (TF_j^iw_j)}{\sqrt{\sum_{j = 1}^m TF_j^iw_j}} \text{, where $\mathbf{d}^i$ can be stored in a dedicated file.}\]

\chapter{Clustering}
\section{Defining clustering}
A clustering algorithm partitions a dataset $\displaystyle \mathcal{D} = \{\mathbf{x}_i\}_{i = 1}^n$ into non-overlapping groups such that the data points in the same cluster are closer to each other than to the points belonging to other groups.
\section{Hierarchical clustering}
Hierarchical clustering is an unsupervised learning method that produces a tree-like hierarchy of clusters that can be visually summarised using a dendrogram.
\begin{figure}[H]
    \centering
    \includegraphics[width=0.45\linewidth]{images/hierarchical_clustering.png}
    \caption{Example of hierarchical clustering and the resulting dendrogram.}
    \label{fig:hierarchical_clustering}
\end{figure}
\noindent Hierarchical methods can be implemented as top-down ``divisive'' algorithms, which recursively split large clusters into smaller and heterogeneous sub-clusters, or bottom-up ``agglomerative'' algorithms, which treat each data point as an individual cluster and iteratively merge close clusters until all data points belong to the same root cluster. \newline
Overall, hierarchical clustering provides a flexible approach to data visualization because it does not require a predefined number of clusters, although it tends to be computationally expensive. \newline
In fact, keeping track of all cluster distances requires $\displaystyle O(n^2)$ time for each of the $\displaystyle n$ iterations, resulting in a total complexity of $\displaystyle O(n^3)$. \newline
However, this complexity can be reduced to $\displaystyle \Theta(n^2\log(n))$ by introducing a min-heap to efficiently keep track of cluster distances.
\section{Partitional clustering}
Partitional clustering is an unsupervised learning algorithm that, given a dataset $\displaystyle \mathcal{D} = \{\mathbf{x}_i\}_{i = 1}^n$, with $\displaystyle \mathbf{x}_i \in \mathbb{R}^d \text{ } \forall i$, and an integer $\displaystyle K > 0$, aims to split the dataset into a $\displaystyle K$-partition. \newline
In particular, a $\displaystyle K$-partition over a dataset $\displaystyle \mathcal{D}$ is defined as a collection of (non-empty) sets $\displaystyle C_1, \dots, C_K \subseteq \mathcal{D}$ such that $\displaystyle C_i \cap C_j = \emptyset \text{ } \forall i \neq j$ and $\displaystyle C_1 \cup \dots \cup C_K = \mathcal{D}$. \newline
Generally speaking, partitional clustering is performed through the $\displaystyle K$-means optimization problem, which, for a dataset $\displaystyle \mathcal{D}$, aims to find a $\displaystyle K$-partition and a sequence of representatives $\displaystyle \mathbf{c}_1, \dots, \mathbf{c}_K \in \mathbb{R}^d$ that minimize the objective function
\[\mathcal{L}(C_1, \dots, C_K, \mathbf{c}_1, \dots, \mathbf{c}_k) = \sum_{j = 1}^K\sum_{\mathbf{x}_i \in C_j} \lVert \mathbf{x}_i - \mathbf{c}_j \rVert_2^2\]
More specifically, it is possible to show that the optimal solution to this problem corresponds to the centroids of each cluster, which are defined as
\[\mathbf{c}_j = \frac{1}{|C_j|}\sum_{\mathbf{x}_i \in C_j} \mathbf{x}_i\]
\begin{figure}[H]
    \centering
    \includegraphics[width=0.45\linewidth]{images/partitional_clustering.png}
    \caption{Example of partitional clustering using $\displaystyle K$-means.}
    \label{fig:partitional_clustering}
\end{figure}
\begin{proofbox}
    Since clusters are independent of one another, it is sufficient to optimize
    \begin{align*}
        \mathcal{L}_j &= \sum_{\mathbf{x}_i \in C_j} \lVert \mathbf{x}_i - \mathbf{c}_j \rVert_2^2 \text{ for each centroid $\mathbf{c}_j$, resulting in} \\
        \frac{\partial\mathcal{L}_j}{\partial\mathbf{c}_j} &= \sum_{\mathbf{x}_i \in C_j} -2(\mathbf{x}_i - \mathbf{c}_j) \\
            &= -2\sum_{\mathbf{x}_i \in C_j} \mathbf{x}_i + 2\sum_{\mathbf{x}_i \in C_j} \mathbf{c}_j = 2|C_j|\mathbf{c}_j - 2\sum_{\mathbf{x}_i \in C_j} \mathbf{x}_i = 0 \Leftrightarrow \mathbf{c}_j = \frac{1}{|C_j|}\sum_{\mathbf{x}_i \in C_j} \mathbf{x}_i
    \end{align*}
\end{proofbox}
\noindent Overall, the main issue of partitional clustering lies in the fact that $\displaystyle K$-means is an $\displaystyle \mathbf{NP}$-hard problem because the optimization procedure requires $\displaystyle O(K^n)$ time. \newline
For this reason, partitional clustering is often performed using $\displaystyle (1 + \varepsilon)$-approximation algorithms whose running time is $\displaystyle O(n^{\frac{1}{\varepsilon}})$, often requiring to consider a trade-off between computational complexity and approximation quality.
\subsection{Approximating $K$-means using Lloyd's method}
Lloyd's method is a popular greedy approximation algorithm for the $\displaystyle K$-means problem. \newline
This algorithm starts with an initialization phase, where $\displaystyle K$ representatives are chosen at random, followed by an iterative phase that consists of an assignment step, where each data point is assigned to the cluster represented by its nearest centroid, and an update step, where each centroid is updated to minimize the objective function, going on until convergence.

\begin{algorithm}[H]
    \caption{Lloyd's method.}
    \KwData{A dataset $\displaystyle \mathcal{D} = \{\mathbf{x}_i\}_{i = 1}^n$ and an integer $\displaystyle K > 0$.}
    \KwResult{A $K$-partition $\displaystyle C_1, \dots, C_K$ of the dataset and a sequence of centroids $\displaystyle \mathbf{c}_1, \dots, \mathbf{c}_K$.}

    Choose $\displaystyle K$ random centroids $\displaystyle \mathbf{c}_1, \dots, \mathbf{c}_K$\;
    \While{not converged}{
        \ForEach{$\displaystyle \mathbf{x} \in \mathcal{D}$}{
            Assign $\displaystyle \mathbf{x}$ to the cluster $\displaystyle C_j$ corresponding to $\displaystyle \arg\min_{j \in \{1, \dots, K\}} \lVert \mathbf{x} - \mathbf{c}_j \rVert_2^2$\;
        }
        \For{$j \gets 1, \dots, K$}{
            $\mathbf{c}_j \leftarrow \frac{1}{|C_j|} \sum_{\mathbf{x} \in C_j} \mathbf{x}$\;
        }
    }
    \Return{$C_1, \dots, C_K$, $\mathbf{c}_1, \dots, \mathbf{c}_K$}\;
\end{algorithm}
\noindent While several criteria for convergence can be defined, this algorithm considers convergence to be reached when the objective function $\displaystyle \mathcal{L}$ does not change significantly across iterations. \newline
In fact, since $\displaystyle \mathcal{L}$ is defined to be a non-negative function and Lloyd's method ensures that the objective function does not increase across iterations, the algorithm is guaranteed to terminate. \newline
However, this approximation algorithm is not optimal because the solution is locally optimal depending on the initialization phase.
\begin{figure}[H]
    \centering
    \includegraphics[width=0.55\linewidth]{images/lloyds_method_solutions.png}
    \caption{Different solutions provided by Lloyd's method for the same $\displaystyle K$-means problem.}
    \label{fig:lloyds_method_solns}
\end{figure}
\noindent Overall, while the worst-case scenario requires exponential time, Lloyd's method normally converges in $\displaystyle O(TnK)$ time if convergence is reached after $\displaystyle T$ iterations.
\subsection{Approximating $K$-means using the $K$-means$++$ algorithm}
$\displaystyle K$-means$\displaystyle ++$ is an approximation algorithm that aims to improve the initialization phase of Lloyd's method by ensuring that the initial centroids are as far as possible from each other. \newline
In fact, if the set $\displaystyle A = \{\mathbf{c}_1, \dots, \mathbf{c}_m\}$ keeps track of the already selected centroids, the next centroid $\displaystyle \mathbf{c}_{m + 1}$ will be chosen according to the following probability distribution:
\[\mathbb{P}(\mathbf{c}_{m + 1} = \mathbf{x}) = \frac{d_A(\mathbf{x})^2}{\sum_{\mathbf{y} \in \mathcal{D}} d_A(\mathbf{y})^2} \text{, where $d_A(\mathbf{x}) = \min_{\mathbf{c} \in A}\{\lVert \mathbf{x} - \mathbf{c} \rVert_2\}$.}\]
After selecting the initial centroids, this algorithm proceeds with the same iterative phase implemented Lloyd's method, going on until convergence.

\begin{algorithm}[H]
    \caption{The $\displaystyle K$-means$\displaystyle ++$ algorithm.}
    \KwData{A dataset $\displaystyle \mathcal{D} = \{\mathbf{x}_i\}_{i = 1}^n$ and an integer $\displaystyle K > 0$.}
    \KwResult{A $K$-partition $\displaystyle C_1, \dots, C_K$ of the dataset and a sequence of centroids $\displaystyle \mathbf{c}_1, \dots, \mathbf{c}_K$.}

    Choose a centroid $\displaystyle \mathbf{c}_1$ uniformly at random\;
    $\displaystyle A \gets \{\mathbf{c}_1\}$
    \For{$\displaystyle j \gets 2, \dots, K$}{
        Choose $\displaystyle \mathbf{c}_j = \mathbf{x}$ with probability $\mathbb{P}({\mathbf{x}}) = \frac{d_A(\mathbf{x})^2}{\sum_{\mathbf{y} \in \mathcal{D}} d_A(\mathbf{y})^2}$\;
        $\displaystyle A \gets A \cup \{\mathbf{c}_j\}$\;
    }
    \While{not converged}{
        \ForEach{$\displaystyle \mathbf{x} \in \mathcal{D}$}{
            Assign $\displaystyle \mathbf{x}$ to the cluster $\displaystyle C_j$ corresponding to $\displaystyle \arg\min_{j \in \{1, \dots, K\}} \lVert \mathbf{x} - \mathbf{c}_j \rVert_2^2$\;
        }
        \For{$j \gets 1, \dots, K$}{
            $\mathbf{c}_j \leftarrow \frac{1}{|C_j|} \sum_{\mathbf{x} \in C_j} \mathbf{x}$\;
        }
    }
    \Return{$C_1, \dots, C_K$, $\mathbf{c}_1, \dots, \mathbf{c}_K$}\;
\end{algorithm}
\noindent For an instance of the $\displaystyle K$-means problem where $\displaystyle \mathcal{O}$ denotes the cost of the optimal solution while the random variable $\displaystyle \mathcal{L}$ indicates the cost of a solution returned by the $\displaystyle K$-means$\displaystyle ++$ algorithm, it is possible to prove that $\displaystyle \mathbb{E}(\mathcal{L}) \leq \mathcal{O}\log(K)$.
\subsection{Special cases of the $K$-means problem}
When choosing $\displaystyle K = 1$ or $\displaystyle K = n$, the $\displaystyle K$-means algorithm is guaranteed to run in polynomial time because the optimal solution is trivial.
\begin{proofbox}
    Consider a dataset $\displaystyle \mathcal{D} = \{\mathbf{x}_i\}_{i = 1}^n$: when performing $\displaystyle K$-means with one cluster, all the data points are assigned to the same cluster, which corresponds to the dataset, meaning that
    \[\mathcal{L}(\mathcal{D}, \mathbf{c}) = \sum_{i = 1}^n \lVert \mathbf{x}_i - \mathbf{c} \rVert_2^2 \text{, resulting in } \frac{d\mathcal{L}}{d\mathbf{c}} = \sum_{i = 1}^n -2(\mathbf{x}_i - \mathbf{c}) = 0 \Leftrightarrow \mathbf{c} = \frac{1}{n}\sum_{i = 1}^n \mathbf{x}_i\]
    For $\displaystyle K = n$, each data point acts as an individual cluster, meaning that the loss function is trivially minimized by considering $\displaystyle \mathbf{c} = \mathbf{x} \text{ } \forall \mathbf{x} \in \mathcal{D}$.
\end{proofbox}
\noindent Additionally, whenever the data points are one-dimensional, an optimal solution can be found in polynomial time using a dynamic programming algorithm.
